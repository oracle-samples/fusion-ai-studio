# Configure OAuth for AI Studio CLI

This guide explains how to create and configure a public OAuth client in Oracle Identity Cloud Service (IDCS) for use with AI Studio CLI.

## 1. Before You Begin

Have the following information available:

- Permission to create and activate integrated applications in the target IDCS environment or domain.
- The environment identifier required for the resource scopes.
- The target environment URL.
- The Fusion AI Studio extension installed in Visual Studio Code (VS Code).
- The AI Studio Codex skill installed under the `.agents/skills` directory structure.

## 2. Create the Public Client

1. Open the Oracle IDCS console for the environment or domain in which you want to enable AI Studio CLI.
2. Under Identity and Security, open the **Integrated applications** tab and select **Add application**.
3. Select **Mobile Application**. This registers the application as a public OAuth client.
4. Click on **Launch Workflow** to proceed.
5. In **Add Mobile Application**:
   - Enter an application name and a description.
   - Leave custom URLs blank unless they are required for your application.
   - Turn on **Display in My Apps**.
6. Select **Submit** to create the application.

> **Important:** The **Application ID** shown on the details page is not used for the CLI configuration described later. Use the **Client ID** from the OAuth configuration tab instead.


## 3. Open OAuth Configuration

1. On the application details page, select the **OAuth configuration** tab.
2. Select **Edit OAuth configuration**.


## 4. Configure OAuth Settings

In the OAuth configuration editor, configure the following settings:

1. Under **Allowed grant types**, enable:
   - **Authorization code**
   - **Refresh token**
   - **Implicit**
2. Leave **Device code** unselected.
3. Enable **Allow non-HTTPS URLs**.
4. Add these redirect URLs:
   - `http://127.0.0.1:43188/callback`
   - `urn:ietf:wg:oauth:2.0:oob`
5. Set both **Post-logout redirect URL** and **Logout URL** to:

   ```text
   http://127.0.0.1:43188/logout
   ```

6. Review the logout and consent settings, and leave **Bypass consent** turned off.


## 5. Add the Resource Scope

1. Under **Token issuance policy** section, enable **Add resources**.
2. Select **Add scope**.
3. Search for and select **Oracle Fusion AI Cloud (Spectra)**, then grant its required scope.
4. Search for and select **Oracle Boss Cloud (Spectra)**, then grant its required scope.
5. Save the OAuth configuration by clicking on **Submit**.

**Expected result:** The OAuth configuration is saved successfully.


## 6. Copy the Client ID and Activate the Client

1. Return to the **Details** tab and confirm that the application type is **Mobile Application** and displayed property values are shown correctly.
2. Open the **OAuth configuration** tab and copy the **Client ID**.
3. From the **Actions** menu, select **Activate** to activate the created app.


**Expected result:** The client status is **Active**, and the OAuth **Client ID** has been copied.


## 7. Configure AI Studio CLI in Oracle Fusion AI Agent Studio

1. Sign in to the environment and open Oracle Fusion AI Agent Studio.
2. In AI Studio, open **Credentials**, then select the **AI Studio CLI** tab.
3. Select the **Enable AI Studio CLI** checkbox.
4. Enter the IDCS **Client ID** (copied in the previous step) in the AI Studio CLI **Application ID** field.
5. Save the configuration. AI Studio generates content in the `env.properties` section on the page.
6. Copy the `env.properties` content generated by AI Studio; this will be used for local development setup.
7. Verify that the completed configuration matches the instructions in the **Create a public client in Oracle IDCS** collapsible section on the page.

**Expected result:** AI Studio saves the CLI configuration and displays the generated `env.properties` content.


### OAuth IDCS Configuration Checklist

- [ ] The client is a **Mobile Application** in Oracle IDCS.
- [ ] **Authorization code**, **Refresh token**, and **Implicit** are enabled.
- [ ] The redirect and logout URLs match the values in this guide.
- [ ] **Allow non-HTTPS URLs** is enabled.
- [ ] The application is activated.
- [ ] AI Studio uses the IDCS **Client ID**, not the IDCS Application ID.

## 8. Set Up Authentication in VS Code

1. Start VS Code and open the workspace directory.
2. Open the command palette using the shortcut `Cmd+Shift+P` on macOS or `Ctrl+Shift+P` on Windows or Linux.
3. Search for and select `Fusion AI Studio: Configure Authentication`.
4. Select **OAuth / Token Authentication**.
5. Enter the environment URL. VS Code should open `env.properties` and display a prompt to paste the OAuth or token properties.
6. If the file does not open automatically, open it manually.
7. Verify that the file already has properties such as `aistudio.dev-mode` and `aistudio.fa-host`.
8. Merge the copied `env.properties` content into the local file: add properties that are missing, and replace the value of an existing generated property instead of adding the same property a second time. Keep unrelated existing properties.
9. In VS Code, open **Terminal** > **New Terminal**, then run the following authentication command:

  ```bash
  node .agents/skills/aistudio/scripts/aistudio.js authenticate
  ```

10. This opens a browser where you can complete authentication.
11. Alternatively, ask Codex to initiate authentication with a prompt such as `initiate aistudio authentication`.
12. After authentication completes successfully, you can connect to the environment, fetch AI Studio objects from the environment, and save AI Studio objects to the environment.

**Expected result:** Complete sign-in in the browser, then return to VS Code. The command should complete without an authentication error.

### If Authentication Does Not Complete

- Confirm that VS Code opened the intended workspace directory and that `.agents/skills` is available in that workspace.
- Confirm that Node.js is available in the VS Code terminal by running `node --version`.
- Confirm that the environment URL is for the same environment configured in AI Studio.
- If the browser does not open or sign-in is interrupted, run the authentication command again and complete the browser sign-in before closing the page.

### Local Authentication Checklist

- [ ] An `env.properties` file is present.
- [ ] The properties from the Fusion AI Studio **AI Studio CLI** tab have been merged into the local `env.properties` file without duplicate property keys.
- [ ] Authentication was initiated and completed successfully.
- [ ] A follow-up fetch or related AI Studio operation succeeds after authentication.

## Summary
This guide describes the end-to-end process for creating a public client in Oracle IDCS, enabling AI Studio CLI in Oracle Fusion AI Agent Studio, and configuring OAuth authentication in VS Code to support local Fusion AI development.

After completing the configuration, you will be able to:

- Connect to the target environment from VS Code.
- Develop Fusion AI artifacts locally by using VS Code with Codex assistance.
- Fetch AI Studio objects from the environment.
- Save AI Studio objects to the environment.
